# Run With Love CRM (MVP)

Внутренняя CRM-система для команды организаторов забегов.  
Проект развивался как живой MVP под изменения от заказчика после созвонов.

## Что это сейчас

- Рабочий внутренний контур на Django Admin + минимальный web UI.
- Основные бизнес-сущности: ивенты, клиенты, заказы, позиции заказа, склад, задачи, импорт Excel.
- Фокус на операционной работе команды, а не на публичном API.

## Реализованные возможности

### 1) Операционная часть

- Управление `Event`, `Client`, `Order`, `OrderItem`, `Product`, `StockLocation`, `StockItem`, `Task`.
- Архивные прокси-модели для задач и заказов (`ArchiveTask`, `ArchiveOrder`).
- Кастомизированный Django Admin dashboard.

### 2) Роли и доступ (по фактической логике кода)

- `Owner/Admin`: расширенный доступ к задачам и заказам.
- `Packer`: доступ только к назначенным заказам/задачам в админке.
- Для `Packer` в админке реализован режим read-only по назначенным объектам.

Примечание: в мобильном workspace сейчас есть обновление статусов через POST для доступных объектов.

### 3) Импорт Excel

- Поддержка `.xlsx`.
- Поддержка `.xls` через конвертацию в `.xlsx`.
- Хранение сырой строки импорта в `RawExcelRow.raw_data`.
- Создание/обновление `Client` по телефону.
- Создание `Order` и `OrderItem` из строки Excel.

### 4) Складская логика

- Проверка остатков и списание при создании `OrderItem`.
- Возврат остатка при удалении `OrderItem`.
- Защита от изменения `quantity` у существующей позиции (через валидацию модели).

### 5) Фоновая обработка

- Подключен Celery.
- Брокер/бэкенд результатов через Redis (переменные `CELERY_*`).
- Фоновая задача обработки импорт-пакета.

## Текущий стек

- Python, Django
- PostgreSQL
- Celery + Redis
- openpyxl, pandas/xlrd (импорт и конвертация Excel)

## Структура проекта

- `apps/clients` — клиенты
- `apps/events` — ивенты/забеги
- `apps/orders` — заказы и позиции
- `apps/stock` — товары и склад
- `apps/tasks` — задачи
- `apps/imports` — импорт Excel и связанная логика
- `apps/webui` — минимальный UI (landing/workspace/mobile)
- `config` — настройки Django/Celery/urls
- `templates`, `static` — шаблоны и статика

## Запуск (локально, текущий режим)

1. Подготовить PostgreSQL и Redis.
2. Создать `.env` с параметрами БД и Django (пример переменных ниже).
3. Выполнить миграции:
   - `python manage.py migrate`
4. Создать администратора:
   - `python manage.py createsuperuser`
5. Запустить сервер:
   - `python manage.py runserver`
6. (Опционально) запустить Celery worker:
   - `celery -A config worker -l info`

Минимально нужные переменные окружения:

- `DJANGO_SECRET_KEY`
- `DEBUG`
- `ALLOWED_HOSTS`
- `DB_NAME`
- `DB_USER`
- `DB_PASSWORD`
- `DB_HOST`
- `DB_PORT`
- `CELERY_BROKER_URL`
- `CELERY_RESULT_BACKEND`

## Что пока не формализовано

- Docker/Docker Compose в репозитории отсутствуют.
- Swagger/OpenAPI не подключены как отдельный контрактный слой.
- Публичный DRF API не выделен (проект сейчас админко-ориентированный).
- README по запуску/эксплуатации добавлен в этой версии, но инфраструктурный контур еще будет дополняться.
